## 测试场景覆盖矩阵

| 场景ID | 测试方法 | 入参 | 断言 | 通过条件 |
|:------|:--------|:-----|:-----|:--------|
| TC-01 | testBasicOfferPoll | type, capacity | offer 两个元素后 peek/poll 顺序一致 | "a".equals(peek) && "a".equals(poll) && "b".equals(poll) && poll()==null && isEmpty() |
| TC-02 | testNullRejected | type, capacity | offer(null) 抛出 NPE | 捕获 NullPointerException 后 rejected==true |
| TC-03 | testFullAndEmpty | type（有界） | 容量 2 时第 3 个 offer 返回 false，出队后可继续入队 | offer(1) && offer(2) && !offer(3) && poll()==1 && offer(4) |
| TC-04 | testSpscConcurrency | 1P/1C | 单生产者写入 1..N，单消费者累加 | 消费者累加和 == N*(N+1)/2 |
| TC-05 | testMpmcConcurrency | 4P/4C | 多生产者写入 0..4N-1，多消费者累加 | 累加和 == 4N*(4N-1)/2 && remaining==0 |
| TC-06 | testUnboundedConcurrency | 4P/4C | 多生产者写入 0..4N-1，多消费者累加 | 累加和 == 4N*(4N-1)/2 && remaining==0 |

> 说明：TC-04/05/06 元素总量为 100_000 * 4 = 400_000，生产者写入全局唯一值，
> 消费者取出的累加和用于校验无丢失、无重复、无串读。SPSC 使用 1P/1C 线程约束。
